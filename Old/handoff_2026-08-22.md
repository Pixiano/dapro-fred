## Presence detection + sleep mode — built out to full scope

symmetrical present-streak gate, `678eba0`) and grew through the day
into a real system:

- **Wake greeting** (`d2ea858`, later fixed `cb7c599`) — speaks on the
  real `is_sleeping()` True→False edge, gated on a genuine sleep-mode
  wake rather than a single-poll blip.
- **Consolidation** (`65bc1c3`, `23ffb38`) — auto-writes a day-summary
  and MAP.md gap-log entry on wake, LLM-polished into one short
  sentence, no confirmation needed. `cea7cb0` later stopped it from
  piling up duplicate `**Recap — HH:MM:**` lines when it fires several
  times in a quiet hour with nothing new to say.
- **Deep vault-reflection** (`5bde118`) — a new "Reflect" tier
  (gpt-oss-20b, medium reasoning effort, Vatsal's explicit model
  choice), gated on 30+ new session events per sleep window so it
  doesn't fire on every nap. Friend-file writes are free-reign
  (writes directly); self-observations stage to
  `personal/pending-review/` and get offered back on the next wake —
  JARVIS-style "review the changes, or continue?" — with a recurring
  nudge until reviewed. Never writes if presence returns mid-pass.
- **Family/stranger recognition + security watch** (`1125959`) — a
  separate binary family-classification pass in `presence.py`
  (`last_classification()`), `enroll_face.py --person NAME` to
  populate `family_enrollment.json`, and a new
  `orchestrator/security_watch.py`: a 5s poll that auto-engages
  lockdown after a debounced stranger-at-the-desk detection, bundles a

  (`confirm_lockdown_lift` tool). **Built, code-complete, tested —
  but unpopulated.** No family member has actually been enrolled yet;
  needs a human to run `enroll_face.py --person NAME` per family

## Real bugs found and fixed via live log investigation

All of these were root-caused from `session_2026-08-22.jsonl`, not
guessed at:

- **Dispatcher pronoun-routing gap** (`4a9364c`) — "Open that folder."
  right after `create_text_file` fell through to `launch_application`
  with `app_name="that folder."`, burning ~27s exhaustively searching
  PATH/registry/Start Menu before failing. The same pronoun-fragment
  bug ("open her file", "open it for me please", ...) had recurred
  across 5+ sessions since 2026-08-03. Fix: `_route_launch_application`
  now declines (falls through to the LLM path) when the target starts
  with a bare pronoun, mirroring the guard `_route_web_search` already
  had; the pronoun-open fast path now also matches "open that
  folder"/"the folder"; `create_text_file`/`create_folder` now record
  their result via `found_cache.set_last` so there's something for
  `open_last_found` to resolve against.
- **Dropped wake greeting** (`cb7c599`) — two `notify()` calls fired in
  the same tick on a real presence wake (consolidation's recap,
  `check_presence`'s greeting), both racing for
  `pill_app._speak_proactive`'s single `turn_lock`; the second silently
  lost the non-blocking lock race and never spoke. Fixed by folding the
  greeting into consolidation's existing bundled-message mechanism
  instead of firing a second, competing `notify()`.
- **Thinking-block leaks, two call sites** (`56dca31`) —
  `summarise_today`/`_polish_recap`'s prompts are bulk data dumps
  (a day's requests, a raw recap to polish), routinely over
  `THINKING_LENGTH_THRESHOLD` by raw character count, so
  `llm_client._native_call`'s length-based `enable_thinking` guess
  turned reasoning on for tasks that never needed it — and the
  model's reasoning came out as untagged `"Thinking Process:"` prose
  (no `<think>`/`<|channel>` marker), so `_strip_thinking` didn't catch
  it and it was spoken verbatim. Added `generate()`'s
  `force_no_thinking` override param (same shape as
  `describe_image`'s existing override) and extended `_strip_thinking`
  to also treat an untagged `"Thinking Process:"` prefix as unfinished
  reasoning, as a defensive backstop.
- **"Save it" cue-routing gap** (`cea7cb0`) —
  `preview_session_summary`'s own output tells the user to say "Say
  save it to confirm," but "Save it." only matched the `files`
  category (bare "save" cue there), so `save_today_summary` was never
  in the offered tool menu — the model picked `create_text_file` from
  the files menu instead and overwrote the real daily note with a
  fabricated one. Fixed by adding "save it" as a `recap` cue,
  additive alongside `files`.
- **Duplicate auto-write recap spam** — same commit as above:
  `consolidation.on_sleep_enter` can fire several times an hour;
  `save_session_summary` now skips the write when the new recap text
  matches the most recent one already in the file.
- **Multiline-text logging crash** — `render_pill`'s transcript now
  collapses embedded newlines before measuring text width;
  `draw.textlength()` raises `ValueError` on multiline input, which was
  logged as a spurious `"proactive_speech"` error (`"can't measure
  length of multiline text"`, confirmed live in
  `session_2026-08-22.jsonl`) every time a multiline reminder/greeting
  spoke. Landed as part of `4a9364c`.

## Single-instance guard (`7428b05`)

`fred_popup.py` had no protection against a second launch while one
was already running — the `wmic`-based guard had been dropped earlier
(`16d49ef`) with nothing replacing it. `SO_REUSEADDR` lets Windows bind
an already-bound port without erroring, so two live instances could
end up nondeterministically splitting HUD-server/phone-API requests
between them — a real correctness risk, not just wasted resources.
Added `Core/utils/process_group.py`'s sibling, `Core/utils/
single_instance.py`: a PID lock file with `psutil.pid_exists` liveness
checking (a stale lock from a hard kill is treated as free), wired
into `fred_popup.py`'s `main()` before anything spawns. `restart_fred()`
releases its own lock first since it deliberately spawns its
replacement while still alive.

Logged directly into `MVP Plan (v1.0 - v1.1).txt`, Vatsal's call: a
huge amount of real feature work has shipped since v1.0, well beyond
that plan's original scope, and needs a deliberate hardening pass
before the tool-surface freezes for fine-tuning — not new feature

legible. Ordered sequence:

1. **Local-first pass, Pi migration where plausible** — move what can
   reasonably run local to local; revisit the Raspberry Pi migration
   question (presence/face-recognition identified as the strongest
   candidate — CPU-only already, but not currently isolated from
   FRED's single-process architecture, and `buffalo_l`'s real
   performance on Pi-class ARM is unverified, not just unoptimized).

   migration, for real bugs (same log-driven standard as this
   session), robustness, verbose failure logging, LOC reduction where
   it doesn't cost clarity, dependency/pattern re-evaluation, and a
   modularity refactor pass where today's fast-moving work drifted.
   Fully documented, both locally and in the actual GitHub repo.
3. **A handoff file for future agents** — explaining the freeze, why
   it's frozen, how it got frozen, and what's next.
