Internal reference — as built, not as planned

Everything F.R.E.D. can currently do

A tool-by-tool, mechanism-by-mechanism account of the running system: what a spoken request actually triggers, which model answers it, and why. Every behavior below is read from the live code, not from a spec.

49 tools 1 model resident at a time Qwen3-8B default tier CUDA / RTX 5060 Ti 4 confirm-gated actions

Architecture

How a request is handled

Every spoken turn passes through the same six-stage pipeline, in this order, and most turns exit early — the expensive stages only run when a cheaper one couldn't answer.

01

The dispatcher zero LLM calls

A fixed list of regular expressions, checked top to bottom, for phrasing so unambiguous it doesn't need a model's judgment: "open Spotify", "what time is it", "turn it up a bit", "open it". A match executes immediately. This is why some replies come back in well under a second while others take several — the ones that hit here never touch the model at all.

02

Canned replies

A small set of purely social exchanges (acknowledgements, thanks) answered from a fixed pool, same zero-LLM reasoning as the dispatcher.

03

Intent classification narrows the menu

Anything the dispatcher didn't recognize is classified as chat or action. Chat skips tools entirely — this is the fix for a small model picking a random tool because "reply normally" was never on the menu. An action turn is matched against ~14 keyword categories (files, audio, git, …); matched categories are unioned into a short candidate list — typically 2–8 tools instead of all 49 — narrowed further by a semantic embedding ranker. Only if no cue matches at all does this fall back to asking the model directly.

04

The tool-calling turn 1 model call

The narrowed tool list is offered to the resident model, which either answers directly or requests one or more tool calls. If a requested tool is destructive (see below), execution stops here and a confirmation question is returned instead — nothing runs yet.

05

Execution + the phrasing pass +1 model call

The tool runs, and its raw result goes back to the model for a second, short call that turns it into something worth saying aloud — unless the tool already returns a full sentence (get_weather, set_volume, reminders, …), in which case that second call is skipped outright and the raw string is spoken as-is.

06

Speech

The reply streams to Kokoro sentence-by-sentence as it's generated — see the voice pipeline for how that overlaps with generation instead of waiting for it to finish.

Two worked examples

Say
What's the weather?
Path
Stage 01 only. The dispatcher's weather pattern matches, get_weather() runs immediately against wttr.in, and the returned sentence is spoken directly — the model is never invoked for this turn at all.
Say
Find my health logs
Path
Stages 01 → 03 → 04 → 05. No dispatcher pattern fits "find my X"; the files category matches on find; the model is offered search_files/find_file_smart/etc. and picks find_file_smart, which itself runs its own short internal loop (see Files) before the result comes back for phrasing.

Architecture

The model & reasoning tiers

Four model tiers are configured. In practice, almost every turn today runs on exactly one of them.

TierModelContextReasoningIn use today
StandardQwen3-8B, Q4_K_M24,576 tok On by defaultEvery turn — the default and only tier the live pipeline requests
BackupQwen3.5-4B, Q6_K16,384 tok Off by defaultConfigured, not reachable — kept as a fast fallback if Standard's latency ever needs it
DeepQwen3-14B, Q4_K_M16,384 tok On by defaultNot requested by the live conversation pipeline; used only by the offline vault-ingest converter
Extremegpt-oss-20b16,384 tok "High" (injected)Configured, unverified — largest tier, VRAM budget not yet measured

The "long prompts switch tiers" behavior doesn't actually run right now. A word-count-and-keyword heuristic exists in code — 45+ words plus a signal like "explain" or "debug" would select Deep; 65+ words plus "comprehensive" or "in depth" would select Extreme — but it's gated behind a flag that's currently False. Every request, short or long, technical or casual, is answered by Standard (Qwen3-8B). The heuristic is disabled rather than deleted because a better version of this idea — offering to switch and asking first, rather than silently picking a bigger model — is planned to replace it.

Only one tier is ever resident in memory at once. If a tool explicitly asks for a different tier than whatever's currently loaded, the resident model is unloaded first — there isn't VRAM to hold two at a time on this card, so a tool switching tiers costs a few seconds' reload rather than running alongside the first.

Standard runs with its reasoning ("thinking") turned on: the model works through a hidden <think>…</think> block before answering, which is stripped out before anything is spoken or shown. If a reply runs out of its token budget mid-thought — genuinely still reasoning when the limit hits — the block never closes and there is no answer to give. Rather than say nothing, FRED reports that plainly rather than staying silent.

Tool catalog

Apps & the desktop

launch_application
dispatcher
Open Spotify
Resolves the name through four layers in order — an alias table, PATH, Windows' App Paths registry, then a Start Menu shortcut search — before falling back to a directory scan. STT punctuation ("Spotify.") and trailing filler words ("Spotify now") are stripped first.
open_website
dispatcher
Open youtube.com
Anything shaped like word.word is checked against a list of file extensions first — if it looks like a filename (report.pdf) it opens locally instead of as a URL.
open_path
dispatcher
Open dossier.pdf
Opens a specific file or folder with its default program. A bare filename is checked against Desktop, Downloads, Documents and Pictures before it's reported missing.
open_last_found
dispatcher
Open it / open the second one
Search results are spoken without file paths (paths read aloud is exactly what this avoids), so a follow-up needs its own memory of what was just found — the resolved paths are kept and re-verified against disk before opening.

Tool catalog

Files & search

search_files
LLM-routed
Find spotify.exe
Exact/substring filename match. Walks the folder tree while pruning heavy, irrelevant directories in place (node_modules, .git, package caches, model stores) — a full home-folder search went from 103.6s to 0.7s once this stopped walking into them. Repeats of the same query hit a resolved-path cache instead of re-scanning.
find_file_smart
LLM-routedmulti-step
Find my notes about Suhani
For when the filename itself is unknown. Runs its own small loop, capped at 4 steps: list the current folder, ask the resident model to either descend into a subfolder or declare a match, repeat. Genuinely reasons about folder names rather than string-matching — confirmed live: "notes about a person called Suhani" correctly entered a people/ folder before finding the file.
list_directory
LLM-routed
What's in my Documents folder?
Leads with folder/file counts before listing, so a truncated listing (capped at 40 items) can't silently hide what was actually asked about.
read_file · create_text_file · append_to_file
LLM-routed
Add milk to the shopping list
Append is the quick-capture path — no read/edit/write-back round trip. A bare filename with no path anchors under Documents/FRED, not wherever the process happened to launch from.
move_file · rename_file
LLM-routed
Rename report.txt to report_final.txt
A destination that already exists is refused with a plain sentence rather than crashing on the underlying OS error.
delete_file
confirm required
Delete old_draft.docx
Irreversible. FRED states the file, asks yes/no, and does nothing until you answer.
create_folder
LLM-routed
Create a folder called Taxes
Same Documents/FRED anchoring as the other file tools for a bare name.

Tool catalog

Git

Read-only, on purpose — write access (commit, push) is a different risk category and was deliberately left out.

git_status
LLM-routed
What's my git status?
Branch plus staged/modified/untracked counts. Defaults to the FRED project itself if no path is given, and a guessed or nonexistent path falls back to that same default rather than failing the turn.
git_log
LLM-routed
Show me recent commits
Subjects and relative times only — never raw hashes or diffs in speech.
git_diff_summary
LLM-routed
What's changed but not committed?
File and line-change counts — the actual diff body is exactly the kind of thing that shouldn't be read aloud.

Tool catalog

Web & weather

web_search
dispatcher*
Search for the weather in Paris
*Dispatched instantly for self-contained queries. A query that's pronoun-led ("search it") or names a local scope ("search my desktop") deliberately declines the fast path and falls through to the LLM stage instead, where real conversation history is available to resolve what "it" means. Results never include a URL — a full link read aloud character-by-character is exactly what this avoids — and long result snippets are trimmed at a word boundary.
get_weather
dispatcher
What's the weather?
Via wttr.in, phrased as a sentence rather than glued-together label:value fields. Blank means auto-detected location.

Clipboard & utility

get_clipboard · set_clipboard
LLM-routed
What's on my clipboard?
A copied article or a whole file of code shouldn't commit FRED to minutes of unbroken speech — the read is capped, with the remaining length stated rather than silently cut.
calculate
dispatcher
What's 17% of 300?
Parsed and evaluated by Python's ast module against an explicit operator whitelist — never eval() — so arithmetic is correct by construction instead of pattern-guessed by the model.

Battery, CPU, RAM, disk and uptime as full sentences, not label: value fragments.

Tool catalog

Power & the confirmation gate

power_action
confirm required
Shut down / lock the screen / restart
Lock, sleep, restart and shut down are all here. Everything except lock asks first.

Four tools require confirmation: delete_file, close_window, kill_process, power_action. Once one fires, FRED states exactly what it's about to do — with the real targets named, not the raw arguments — and waits. Anything other than a clear "yes" cancels it; a changed subject or an unrelated new question is treated the same as "no" rather than guessed at.

schedule_reminder · set_timer
LLM-routed
Remind me to call Dad at 7pm
Reminders persist across a restart and fire late rather than being lost if FRED was off past the due time. Timers are always a short relative countdown and are session-scoped.

LLM-routed

Mechanism

The voice pipeline

Listening in, and the reply coming back out, are both built to hide latency rather than eliminate it.

Hearing you

Hold-to-talk: audio records while the hotkey is held, transcribed by Whisper large-v3-turbo the moment it's released. Recording itself needs no model loaded, so capture starts instantly regardless of what else is loading.

Hiding the thinking gap

The instant a turn needs the model, a short filler ("On it.", "Let me have a look.") starts playing while the real reply generates in the background on a separate thread — the two overlap instead of stacking. The filler itself is picked by a cheap word-cue check (social / action / general), not a model call, and every filler and tool-caption phrase is pre-synthesized once and cached to disk, so most turns never re-run Kokoro on "Working on it now." at all.

Speaking the reply

Kokoro synthesizes and plays sentence-by-sentence as the model streams tokens, rather than waiting for the full reply — the first words are audible seconds before the model has finished the rest. Filler, any tool-event caption, and the real reply all play through one continuous audio stream, not three separate ones, specifically so a Bluetooth output's own wake-up ramp only happens once, at the very start of the turn, instead of again right where the real answer begins.

Reasoning (<think> blocks and equivalent) is stripped before anything reaches the TTS layer — the model's working is never spoken, only its conclusion.

Mechanism

Memory & the vault

Two entirely separate long-term stores, both consulted on every turn, doing different jobs.

Long-term memory

Every user/assistant turn, embedded and stored in a local FAISS index — a running record of the conversation itself.

  • Retrieval is cosine similarity over unit-normalized vectors.
  • If the index and the stored record ever disagree on count, it's rebuilt from the record automatically rather than silently returning misaligned results.

The vault

A hand-curated set of markdown files — identity, profile, hard rules, and everything known about people, projects and health — retrieved by semantic search on every turn.

  • Persona, profile and rules load in full, always — never left to a retrieval match.
  • Everything else is chunked, embedded, and the top 6 matching chunks are injected.
  • Tables are flattened to row — Column: value before injection, so a value can never be read out of the wrong column.

Vault content is stated as the only admissible source for a fact about you. The model is explicitly told not to state a number, date or detail that doesn't appear verbatim in what was retrieved, and that a truncated excerpt means missing information — never an invitation to fill in the rest. This exists because it was violated once: asked to review fitness progress, a reply invented a weight, a BMI and a full bloodwork panel that matched nothing in the actual file.

Mechanism

Speaking unprompted

Three background checks run every 15 minutes, each capable of speaking up without being asked — and each fires at most once per stretch, so none of them can turn into nagging.

01

Vault staleness

If active-priorities.md hasn't been updated in 7+ days, FRED says so once — then stays quiet until either it's updated or a further week passes.

02

Long session, no break

Tracks real Windows-level keyboard/mouse idle time. 3 hours of continuous activity with no gap of at least 15 minutes triggers one nudge; any real break resets the clock.

03

Deadline proximity

Any vault file carrying an explicit deadline: date gets flagged once it's within 7 days out. No file uses this field yet — it's the read path for when one eventually does, not a guess at dates from prose.
